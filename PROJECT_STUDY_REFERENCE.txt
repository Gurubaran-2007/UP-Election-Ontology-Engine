This document provides a deep-dive analysis of the project architecture, the tools

--------------------------------------------------------------------------------
1. THE CORE ARCHITECTURE (THE "ENGINE")
--------------------------------------------------------------------------------

A. BACKEND: Node.js with Express Framework
   - Why? Node.js is "Asynchronous," meaning it can handle many API calls (News, 
     AI, Weather) at the same time without freezing.
   - Entry Point: 'server.js' handles all incoming requests from the user and
     decides whether to fetch data from the Database (Neo4j) or an External API.

B. FRONTEND: Vanilla JavaScript, HTML5, CSS3
   - Design Style: "Glassmorphism" (semi-transparent backgrounds with blur).
   - Interaction: Uses 'fetch()' to communicate with our server.
   - Mapping: 
     - 'Leaflet.js' for the India State Map.
     - 'D3.js' for the intricate UP District Map rendering.

C. DATABASE: Neo4j (Graph Database)
   - Unlike Excel/SQL tables, Neo4j stores data as "Nodes" (Dots) and "Relationships"
     (Lines).
   - Example: (District {name: "Lucknow"}) -[:REPRESENTED_BY]-> (Leader {name: "..."}).
   - Host: Hosted on 'Neo4j AuraDB' (Cloud).

--------------------------------------------------------------------------------
2. EXTERNAL TOOLS & DATA SOURCES
--------------------------------------------------------------------------------

A. ARTIFICIAL INTELLIGENCE: Sarvam AI
   - Source: api.sarvam.ai
   - Role: Used for "Strategy Analysis." It doesn't just give text; it returns
     structured JSON data that the frontend uses to draw charts and graphs.

B. REAL-TIME NEWS: NewsData.io
   - Source: newsdata.io
   - Role: Replaced the old Google News RSS because cloud servers (Render.com)
     are blocked by Google. NewsData.io provides a "Developer API" that allows
     server-side fetching.

C. WEATHER DATA: Open-Meteo
   - Source: open-meteo.com
   - Role: A free, non-key-required API used to get live temperature and wind
     speed for Uttar Pradesh.

D. GEOGRAPHICAL DATA (MAPS):
   - India States: TopoJSON/GeoJSON from the 'datameet' community.
   - UP Districts: Custom-filtered GeoJSON from the 'geohacker' India dataset.

3. ADVANCED CODING LOGIC (THE "SMART" PARTS)
--------------------------------------------------------------------------------

A. THE 13-KEY ROTATION SYSTEM (Avoiding API Limits)
   - Logic: NewsData.io has a 200 req/day limit per free account.
   - Implementation: We created an array of 13 keys. 
   - Algorithm: 
     1. Try Key 1.
     2. If the response is "429 Too Many Requests," mark Key 1 as "Exhausted."
     3. Immediately jump to Key 2 and retry the same request.
     4. This allows the site to handle 2,600 requests/day for $0 cost.

B. THE SERVER-SIDE CACHE (Performance & Quota Saving)
   - Logic: If two people click "Lucknow" within 4 hours, the 2nd person shouldn't 
     trigger a new API call.
   - Implementation: Uses a JavaScript 'Map()' object.
   - Expiry: Every data piece has a 'timestamp' (ts). If (Now - ts > 4 hours), 
     the server fetches fresh data. Otherwise, it serves the "Saved" version.

C. THE PROXY SYSTEM (CORS & IP Protection)
   - Logic: Browsers block "Cross-Origin" requests (CORS).
   - Solution: Instead of the browser calling NewsData.io, the browser calls 
     OUR server (/api/up/news), and our server calls NewsData.io. 
   - Benefit: This hides your API keys from the public and bypasses browser blocks.

--------------------------------------------------------------------------------
4. THE DEPLOYMENT PROCESS (LOCAL TO CLOUD)
--------------------------------------------------------------------------------

A. RENDER.COM
   - We connected your GitHub repository to Render.
   - Every time you "Git Push," Render automatically:
     1. Runs 'npm install' to get libraries.
     2. Starts 'node server.js'.
   
B. ENVIRONMENT VARIABLES
   - Sensitive data (Passwords, AI Keys) are stored in Render's "Secret" 
     environment variables so they aren't visible in the code files.

C. SELF-PING (WAKEUP LOGIC)
   - Since Render's free tier sleeps, we added 'setInterval' code that makes
      the server "call itself" every 10 minutes. This prevents it from 
     sleeping during the day.
